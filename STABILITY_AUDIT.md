# STABILITY AUDIT

Версия: 1.0

Статический аудит `main`. Исполнительный код не изменялся.

## Проверено

- структура шаблонов InSales;
- `snippets/head.liquid`;
- `templates/layouts.layout.liquid`;
- `media/theme.scss`;
- `media/theme.js`;
- конфигурационные файлы темы;
- наличие явных `TODO`;
- наличие `console.log`.

## Результат

### 1. Главный layout перегружен дополнительной логикой

`templates/layouts.layout.liquid` содержит одновременно layout, BreadcrumbList, OpenGraph, дополнительные footer-блоки и inline JavaScript.

**Риск:** изменение одной области может затронуть другие страницы.

**Решение:** разделять только после отдельного анализа существующих системных зависимостей InSales. Не выполнять механический рефакторинг.

### 2. OpenGraph реализован непосредственно в layout

Для product/article/collection/page используются разные источники данных, но `og:type` установлен как `website` для всех страниц.

**Риск:** карточки товаров и другие типы контента могут получать менее точную социальную разметку.

**Следующий шаг:** отдельный SEO-аудит перед изменением.

### 3. Schema.org находится в нескольких местах

Organization JSON-LD находится в `snippets/head.liquid`, а BreadcrumbList — в `templates/layouts.layout.liquid`.

Это не является автоматически ошибкой, но требует единой схемы ответственности.

### 4. В layout есть жёстко заданный домен

Встречается `https://veles-legs.ru` непосредственно в шаблоне.

**Риск:** перенос, тестовый домен или изменение домена потребует ручного поиска по шаблонам.

**Следующий шаг:** определить допустимый InSales-механизм получения canonical/base URL и только после этого менять код.

### 5. CSS слишком глобальный

`media/theme.scss` содержит широкие правила для `.widget-type_text a`, `.widget-type_menu a`, `.widget-type_html a` и `.page-content .text-widget a`.

**Риск:** обычные ссылки автоматически превращаются в кнопки, поэтому изменение кнопок может ломать ссылки в несвязанных виджетах.

**Следующий шаг:** инвентаризация фактических кнопок и ссылок перед ограничением селекторов.

### 6. Используется много `!important`

В `media/theme.scss` `!important` применяется практически во всех пользовательских переопределениях шапки, поиска и кнопок.

**Риск:** сложнее предсказать каскад и безопасно расширять тему.

**Следующий шаг:** не удалять массово; сначала определить, какие правила действительно перекрывают системные стили InSales.

### 7. JavaScript-модуль пуст

`media/theme.js` существует, но не содержит пользовательской логики. При этом `templates/layouts.layout.liquid` содержит inline JavaScript.

**Риск:** логика распределена между Liquid и JS-файлами, а заявленный модульный принцип не соблюдается.

**Следующий шаг:** собрать перечень inline-скриптов и только затем переносить их в общий JS-модуль.

### 8. Footer содержит исторический контент

В layout есть блок `«МЕБЕЛЬ-2024»`.

**Риск:** в 2026 году это потенциально устаревшая коммерческая информация.

**Следующий шаг:** подтвердить актуальность данных перед изменением. Автоматически удалять этот блок нельзя.

### 9. Автоматические проверки

В репозитории не найдено явных `TODO` и `console.log` через доступный поиск.

Автоматические тесты пользовательского поведения отсутствуют.

## Ограничение аудита

Проверка реального визуального поведения сайта из текущего окружения не завершена: публичный `https://veles-legs.ru` не был доступен для загрузки через внешний web-доступ.

Поэтому ниже нельзя честно отмечать как выполненные:

- проверку реального отображения главной;
- проверку каталога;
- проверку карточки товара;
- проверку корзины;
- проверку checkout;
- проверку мобильной верстки;
- проверку браузерных JavaScript-ошибок.

Эти пункты остаются задачами этапа 3, а не выдаются за выполненные.
